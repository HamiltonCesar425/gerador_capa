# GERADOR DE CAPAS COM IA

1. OBJETIVO

Modernizar um projeto legado em Python para geração de capas utilizando IA generativa, aplicando progressivamente princípios de Engenharia de Software, testabilidade, segurança, qualidade de código e manutenção.

O projeto também funciona como laboratório prático para estudo de código legado, diagnóstico de falhas, refatoração e testes automatizados.

2. ESCOPO FUNCIONAL

O sistema deve permitir:

RF-01 - Receber o título da capa.

RF-02 - Receber o tema ou estilo visual desejado.

RF-03 - Construir automaticamente um prompt de geração de imagem a partir dos dados fornecidos.

RF-04 - Solicitar a geração da imagem por meio de um serviço externo de IA.

RF-05 - Processar a resposta retornada pelo serviço de geração de imagem.

RF-06 - Salvar localmente a imagem gerada com um nome de arquivo apropriado.

A interface inicial continuará sendo CLI (Command-Line Interface).

3. REQUISITOS DE QUALIDADE

A modernização deverá priorizar:

* código legível e compatível com as boas práticas da linguagem Python;
* separação de responsabilidades;
* baixo acoplamento com serviços externos;
* funções e componentes testáveis de forma isolada;
* tratamento explícito de erros;
* configuração externa de credenciais e parâmetros sensíveis;
* ausência de credenciais no código-fonte e no repositório Git;
* testes automatizados para comportamentos relevantes;
* execução determinística dos testes sempre que possível;
* documentação suficiente para instalação, execução e manutenção;
* dependências declaradas e ambiente reproduzível.

4. DIRETRIZES DE TESTABILIDADE

Antes da criação dos testes, o código legado deverá ser analisado quanto a:

* dependências externas;
* efeitos colaterais (side effects);
* acesso ao sistema de arquivos;
* entrada e saída pelo terminal;
* estado global;
* acoplamento com APIs;
* entradas, saídas e condições de erro.

Serviços externos não deverão ser chamados desnecessariamente durante testes automatizados.

Os testes devem validar o comportamento do Gerador de Capas, e não testar internamente os serviços de terceiros utilizados pelo projeto.

5. MODERNIZAÇÃO DO PROJETO

A evolução será incremental, preservando o histórico Git.

Etapa 1 - Baseline e diagnóstico do legado

* identificar o comportamento existente;
* registrar falhas reproduzíveis;
* identificar problemas de testabilidade;
* analisar dependências e estrutura do projeto.

Etapa 2 - Refatoração para testabilidade

* separar responsabilidades;
* reduzir acoplamentos;
* isolar integrações externas;
* tornar dependências substituíveis durante os testes.

Etapa 3 - Testes automatizados

* criar testes para os comportamentos definidos pelos requisitos;
* testar casos normais, limites e falhas relevantes;
* evitar testes dependentes de rede ou de serviços externos quando não forem testes de integração.

Etapa 4 - Modernização da integração com IA

* utilizar a interface atual e suportada do SDK adotado;
* carregar credenciais de forma segura;
* tratar falhas da API;
* manter a integração isolada do restante da lógica da aplicação.

Etapa 5 - Qualidade e confiabilidade

* análise estática;
* linting e formatação;
* análise de segurança;
* cobertura de testes como métrica auxiliar, sem substituir testes orientados a comportamento;
* logs apropriados para diagnóstico;
* integração das verificações ao fluxo de desenvolvimento.

Etapa 6 - Reprodutibilidade e entrega

* revisar documentação;
* garantir instalação reproduzível;
* avaliar containerização quando houver justificativa técnica;
* preparar o projeto para execução consistente em diferentes ambientes.

6. FUNCIONALIDADES FORA DO ESCOPO ATUAL

Poderão ser avaliadas futuramente:

* redimensionamento e recorte automático de capas;
* inserção programática de textos sobre imagens;
* interface web;
* integração com bots ou outros sistemas;
* suporte a múltiplos provedores de geração de imagens.

Essas funcionalidades não fazem parte da modernização inicial e não devem aumentar desnecessariamente a complexidade do projeto.

7. PRINCÍPIO DE EVOLUÇÃO

Cada alteração relevante deverá responder pelo menos a uma destas perguntas:

* Qual problema está sendo resolvido?
* Qual requisito está sendo atendido?
* Qual risco está sendo reduzido?
* Como a alteração melhora a testabilidade, manutenção, segurança ou confiabilidade?

A modernização deve ser incremental e tecnicamente justificável, evitando refatorações ou abstrações sem necessidade demonstrável.
